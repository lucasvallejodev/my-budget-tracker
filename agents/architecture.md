# Architecture (agent version)

> Summary: the shortest accurate description of how CoinKeeper is built: workspaces (api, web, shared), request flow, the API service, service catalogue, invariants, bootstrap at sign-up and frontend essentials.

## Stack

npm workspaces. API: Fastify 5 · fastify-type-provider-zod · Drizzle ORM 0.45 on PostgreSQL 17 · self-hosted auth (argon2id, cookie sessions) · Zod 4. Web: Next.js 16 App Router (client only) · React 19 · TanStack Query · SCSS · Radix primitives · Recharts · lucide-react (curated registry). Shared: Zod contracts and helpers. Tests: Vitest + PGlite + Testing Library · Playwright (e2e).

## Layers and flow

```
packages/shared  @coinkeeper/shared: Zod request/response contracts (src/schema/*), money/patterns/date/csv helpers (src/lib), constants
apps/web         @coinkeeper/web: Next.js client, no server code, no database
  reads  → React Query hooks  src/components/finance/use-finance-data.ts  → apiGet/apiList/apiPages in src/api/client.ts
  writes → src/api/mutations.ts (one function per write) → apiRequest → then useRefreshFinance() invalidates FinanceKeys
  fetch('/api/v1/…', credentials: same-origin); 401 (not /auth/*) → window to /sign-in?next=…
  next.config.ts   rewrites /api/:path* → ${API_URL}/api/:path* (default http://127.0.0.1:4000, read at build), security headers and the report-only CSP (docs/architecture/security-headers.md)
  src/proxy.ts     page guard: no ck_session / __Host-ck_session cookie → /sign-in?next=…  (validity is checked by the API)
apps/api         @coinkeeper/api: Fastify, owns the database
  plugins/   request-id (X-Request-Id) → security (helmet + API CSP, JSON-only bodies, CORS allow-list, origin check on writes, rate limit) → authentication (cookie → sessions → request.auth) → request user (userId on logs); logging (redaction), audit (security events)
  routes/    <resource>.ts: Zod schemas from @coinkeeper/shared, withErrors(), userIdOf(request), one service call; authenticated scope via requireSession
  modules/   <domain>/service.ts: business rules + SQL, receive a Db handle, throw ServiceError(message, status, code)
  auth/      passwords (argon2id), sessions (SHA-256 token hashes), service (sign-up with bootstrap, sign-in, profile, password), sign-in-throttle (failed sign-ins per email)
  db/        schema.ts (Drizzle tables/enums); migrations in apps/api/drizzle/*.sql
```

`apps/api/src/modules/services.ts` → `createServices(db, { sessionDays, sessionMaxAgeDays })` returns `{ accounts, auth, bootstrap, budgets, categories, db, forecast, fx, getSettings, imports, ledger, listCurrencies, payees, periods, recurring, reports, rules, sessions, templates, updateSettings }`. `buildApp` decorates Fastify with it (`app.services`); tests call `createServices(pgliteDb)` or `createTestApp()`.

## Core rules (do not break)

1. Money = `amount_minor` (bigint, signed: negative out, positive in) + `currency` (char(3)). Parse with `parseAmountInput`, format with `formatMoney`, never floats. Forms send amount **strings**.
2. Balances, net worth, reports and budgets are SQL over `transactions`. Never add cached balance columns. Per-category and income/spending reports read `categoryLines` (`reports/predicate.ts`), which expands split transactions into their `transaction_splits` lines; balances read `transactions`.
3. `kind`: `standard` counts for reports (unless `excluded` or account `counts_in_spending = false`); `transfer` and `opening` count only for balances. DB CHECKs: non-standard rows have no category; `transfer_id` iff `kind='transfer'`.
4. A transfer is exactly two live legs, opposite signs, different accounts, same `transfer_id`, no category or payee. Create/edit/delete/restore both together (`ledger.createTransfer/updateTransfer/removeTransfer/restoreTransfer`).
5. Currency lives on the account (locked once it has transactions) and is copied onto each transaction. Never sum across currencies; group by currency. Conversion only via `fx` and only for the optional converted totals.
6. Categories: `category_groups` own colour + kind; `categories` own icon (a name from `packages/shared/src/constants/icon-names.ts` or one emoji, validated by `iconSchema` in `packages/shared/src/schema/common.ts`; accounts and payees use the same schema for their optional `icon`, with `hexColorSchema` for `color`). The `allowEmoji` setting is a UI preference; the API accepts emoji regardless. Archive, never hard-delete; `archiveCategory(id, moveToId?)` moves rows or flags them `needs_review`.
7. Uncategorised = `category_id IS NULL` + `needs_review = true`. No "Uncategorized" category row.
8. Every query filters by `user_id`; foreign ids → `ServiceError('X not found', 404)`. Every multi-row write is one `db.transaction` with row locks, and set-based: `UPDATE … FROM (VALUES …)` or chunked multi-row inserts with `ON CONFLICT` (helpers in `apps/api/src/modules/batch.ts`), never one query per row, and never a caught database error inside a transaction.
9. Drizzle renders unjoined columns unqualified: inside correlated subqueries write `"accounts"."id"` explicitly.
10. Soft delete, never hard-delete, financial data: `DELETE` sets `deleted_at` on transactions (both legs for transfers), accounts (only without live transactions), rules, transaction templates, budgets and exchange rates; every read, balance, report, budget and conversion filters `deleted_at IS NULL`; `POST …/restore` brings a row back after re-checking the rules (live account, active category, no re-imported duplicate). Categories, groups and payees are archived instead. Only sessions are hard-deleted.

## API service (`apps/api`)

Fastify 5 + `fastify-type-provider-zod`. `buildApp({ config, db })` (`src/app.ts`) registers the Zod compilers, `services` and `config` decorators, the error handler, security (helmet, CORS allow-list `CORS_ORIGINS`, `@fastify/rate-limit`, origin check on writes against `ALLOWED_ORIGINS`), authentication (cookie → `sessions` → `request.auth`), OpenAPI (`/api/docs`) and `routes/` under `/api/v1`. Every route except `/health/live`, `/health/ready` and `/auth/sign-up|sign-in|sign-out` sits in one scope with the `requireSession` hook. Handlers call `userIdOf(request)` and a service; request and response schemas come from `packages/shared/src/schema/`. Services throw `ServiceError(message, status, code)`; the handler answers `{ error: { code, message, fields? } }`. Users and sessions: `src/auth/` (argon2id, SHA-256 token hashes, 30-day sliding sessions capped at `SESSION_MAX_AGE_DAYS` (90) from `sessions.created_at`, after which the row is deleted; `__Host-ck_session` cookie `HttpOnly; SameSite=Lax; Secure` in production). Sign-in and sign-up always issue a new token and delete the session of any cookie the request carried (no fixation); `PUT /me/password` deletes every session of the user and sets a new cookie (`sessions.rotate`). Sign-in is limited per IP (`AUTH_ATTEMPTS_PER_MINUTE`, `@fastify/rate-limit`) and per normalized email (after `SIGN_IN_FAILURES_PER_ACCOUNT` failures, attempts are queued 1 s growing to 5 s apart and refused with `429` only past a 15 s queue; never a lock; `auth/sign-in-throttle.ts`, in-memory and per process, applied before any lookup so unknown emails behave the same). Sign-up seeds settings and taxonomy in the same transaction. `request.ip` (rate-limit key, session IP) is the socket address unless `TRUST_PROXY` lists trusted proxy addresses/CIDRs (default `false`; `true` and hop counts are rejected, because Next.js forwards a client-sent `X-Forwarded-For` untouched). `server.ts` never migrates (Compose runs a one-shot `migrate` service first); on `SIGTERM`/`SIGINT` it calls `shutDown()` (`src/shutdown.ts`): close Fastify, then the pool, within 8 s, exit `0` or `1`. Images run `tini` as PID 1 with exec-form `CMD`. Compose defaults `COOKIE_SECURE=true` and publishes `web` on `127.0.0.1` (`WEB_BIND_ADDRESS`); TLS is terminated by a reverse proxy in front. The pool (`src/db/index.ts`) sets `statement_timeout` = `HANDLER_TIMEOUT_MS` − 1 s (none for `cli/migrate.ts`), `idle_in_transaction_session_timeout` 30 s and `application_name` `coinkeeper-api`, and logs idle-client errors instead of crashing. Full description: `docs/architecture/api.md`; endpoints: `docs/reference/rest-api.md`. Tests: `src/routes/*.test.ts` with `createTestApp()` / `signUp()` from `src/test/app.ts` on PGlite.

Security audit log: call `audit(request, AuditEvents.<event>, { userId?, sessionId?, reason? })` from `src/plugins/audit.ts` for sign-up, sign-in (success, and `signInFailed` with a `reason` such as the error code), sign-out, password change and session revocation. It writes one line `{ audit: '<event>', … }, 'Security event'` through `request.log` (so it carries `reqId`, and `userId` once the session is known): `warn` for `sign_in_failed`, `info` otherwise. `AuditDetails` has no email, password or token field on purpose; never add one. Tests capture the lines with `buildApp({ …, logger: { stream } })`.

Platform: `Fastify({ genReqId, handlerTimeout, connectionTimeout, keepAliveTimeout, requestTimeout, logger })` in `src/app.ts`. Request ids: an incoming `x-request-id` is kept only if it is a UUID (`z.uuid()`), else `randomUUID()`; an `onSend` hook echoes `X-Request-Id` on every reply, errors and 404s included (`plugins/request-id.ts`); `registerRequestUser` runs after authentication and swaps `request.log`/`reply.log` for a child with `userId`. Logging (`plugins/logging.ts`, `loggerOptions`): Pino `redact` (`[REDACTED]`) on `authorization`/`cookie`/`set-cookie` headers and `password`, `currentPassword`, `newPassword`, `passwordHash`, `token`, `tokenHash` fields up to two levels deep; a `logMethod` hook rewrites a `DrizzleQueryError` (top-level argument or `{ err }`) to `Failed query: <sql>` so bound params never reach `msg`, `err.message`, `err.stack` or `err.params`. Log `{ err: error }, 'Fixed sentence'`; a new secret field name goes into `SecretFields`. Timeouts: `HANDLER_TIMEOUT_MS` (default 20 s, 1 to 120 s, below Next's 30 s `proxyTimeout`) → `503 UNAVAILABLE` via the error handler and `request.signal` aborted (the SQL keeps running); `ServerTimeoutsMs` in `constants/http.ts`: `requestTimeout` 30 s, `connectionTimeout` handler + 10 s, `keepAliveTimeout` 72 s (Next's rewrite agent keeps idle sockets without a timeout). Bodies: the `text/plain` parser is removed in `plugins/security.ts`, so any non-JSON body answers `415 INVALID_REQUEST`. CSP: helmet sends `default-src 'none'; frame-ancestors 'none'`; Swagger UI (`/api/docs`) overrides it with `staticCSP` in `plugins/openapi.ts`.

## Bootstrap

At sign-up: `auth.signUp` inserts the user and calls `ensureUserBootstrap(tx, userId)` (`apps/api/src/modules/categories/seed.ts`) inside the same database transaction. It returns early when `user_settings.seeded_version` is set; otherwise, under `pg_advisory_xact_lock(hashtext(userId))`, inserts settings (primary currency EUR by default) and the taxonomy from `default-taxonomy.ts`, then sets `seeded_version`. Nothing bootstraps on later requests.

## Frontend essentials

- Pages are thin; screens live in `apps/web/src/components/finance/<screen>/`. Components are organised in three modules (`ui`, `finance`, `shell`), one folder per component, imported through barrels and depending in one direction, `shell → finance → ui` (`agents/components.md`). Dialogs and pickers are finance components too (`transaction-dialog/`, `account-picker/`, …); `apps/web/src/app/` holds only pages and layouts.
- Reads: hooks + `QueryKeys` in `use-finance-data.ts`, calling `@/api/client` (`apiGet`, `apiList`, `apiPages`; errors are `ApiError` with `status`, `code`, `fields`). Writes: functions in `@/api/mutations` (`deleteTransaction(row)` routes transfer legs to `/transfers/:transferId`), called through `useMutation`/`useEntityMutation`; after a write `useRefreshFinance()` invalidates every key in `FinanceKeys`. Component tests `vi.mock('@/api/mutations', …)` and seed with `client.setQueryData(QueryKeys.…)`.
- Shell: `ApplicationShell` = sidebar (`Navigation` from `app/(main)/routes.ts`: Home, Money (Transactions, Review with a `useNeedsReviewCount` badge, Accounts), Plan (Budgets, Upcoming, Analytics), then Import and Settings; `UserMenu` at the bottom) + `ApplicationHeader` (search, `Ctrl+K` focuses it, opens `/transactions?q=`; global **New transaction** button from `laptop` up) + below `laptop` a bottom `TabBar` (`tab-bar.tsx`: Home, Activity `/transactions`, a round add button opening `TransactionDialog`, Budgets, More opening `NavigationDrawer` with the full navigation and `UserMenu`; `main` gets `size(tab-bar-height)` bottom padding). No header hamburger. `isCurrentPath` (`apps/web/src/lib/navigation.ts`) marks the current entry, sub-pages included. Home is `/`, heading "Home". `app/(main)/page.tsx` renders `Home` (`finance/home/`); `/accounts` renders `AccountsOverview` (`finance/accounts-overview/`); `/analytics`, `/analytics/spending`, `/analytics/cash-flow` and `/analytics/payees` render `Analytics` (`finance/analytics/`) with a `view` and the page's `searchParams`. The old dashboard `Overview` no longer exists: Analytics never repeats Home.
- Auth UI: shell `AuthForm` on `(auth)/sign-in` and `sign-up` (`safeNextPath` in `apps/web/src/lib/navigation.ts` keeps `next` on the app's origin), shell `UserMenu` at the bottom of the sidebar and of the phone navigation drawer, finance `ProfileForm`, `PasswordForm`, `SessionList` in Settings › Profile/Security, finance `DeletedItems` at `/settings/deleted`. `useHydrated()` (`apps/web/src/lib/hydration.ts`) guards data the shell may already have cached from causing hydration mismatches.
- Request and response contracts live in `packages/shared/src/schema/<domain>.ts`: input schemas (`…FormSchema`) and response schemas (`…Schema`) with inferred types (`AccountSummary`, `TransactionRow`, …). API services return those types and routes serialise through them; the client `import type`s them from `@coinkeeper/shared/schema/<domain>`. Enum value lists live in `packages/shared/src/schema/enums.ts` and feed `pgEnum`.
- Styling: one global `.scss` per component holding one BEM block, class names written as plain strings (`cn()` from `apps/web/src/lib/styles.ts` to combine); cascade layers `reset < ui.base < ui < feature`; mobile-first breakpoint mixins and helpers in `apps/web/src/styles/abstracts/`; every design value in the SCSS theme `apps/web/src/styles/theme/` (one light theme), emitted as custom properties by `apps/web/src/styles/tokens.scss` and read through `var(--…)` or the theme functions; Inter (text) and Source Serif 4 (display) via `next/font/google`. Group colour (user data) applied inline.
- Browser-only state: per-viewer conveniences live in `localStorage` and never reach the API: `apps/web/src/lib/form-memory.ts` (last account, transfer pair, `recentCategories` for `CategoryPicker`, `currencyView` for the currency switch on Home, Budgets, Accounts and Analytics) and `finance/review-inbox/reviewed-today.ts` (Review's Undo list, reset daily). Payee brand logos are bundled Simple Icons glyphs (`apps/web/src/constants/brands.ts`); the client never fetches images from a third party.
- Budget periods: every budget, the Home summary and left to spend use the user's period (`periodRange`, `GET /periods/:month`); `BudgetRow.periodFrom`/`periodTo` feed `budgetPeriodOf` in `finance/budget-status.ts`, `Summary.period` feeds the Home heading. Budget status follows the pace of the month: `over` (spent > limit), `fast` (`budgetPace(...).tooFast`: current month, from day 5, the projection, which extrapolates only non-recurring spending and adds `fixedSpentMinor` and `billsDueMinor`, passes the limit), else `ok`; there is no percentage threshold. Compute it only with `budgetFigures` in `finance/budget-status.ts` and read labels and tones from `BudgetStates`. Home, Budgets, Accounts and Analytics show one currency at a time (`CurrencySwitch`); Analytics keeps its filters (`currency`, `month`, `range` 1/3/6/12, `compare` `previous`/`year`) in the URL through `parseAnalyticsFilters` / `analyticsHref` (`apps/web/src/lib/analytics-filters.ts`) and reads data with `useBreakdown(kind, { currency, month, months })` and `useCashFlow(month, months)`; the converted view (`ConvertedView`) is approximate and only on Home.
- Define components at module scope (React Compiler lint forbids components created inside render); avoid `setState` inside `useEffect`.
