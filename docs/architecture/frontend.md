# Frontend

> Summary: how the Next.js client in `apps/web` is organised: pages, feature screens, shared `ui` components, the API client, React Query hooks and mutation functions, the sign-in pages and route guard, the user menu, Settings › Profile and Security, the Deleted items screen, local dates and the current month, pickers and the category autocomplete, Home, the Analytics pages and their URL filters, the Upcoming sections, Accounts, budget status and the currency switch, the phone tab bar, what is remembered in the browser, `useHydrated`, and the styling and state conventions.

`apps/web` has no server code of its own: no route handlers, server actions or database access. Every read and write is an HTTP call to the Fastify API under `/api/v1`, which Next.js forwards (see [Overview](overview.md) and [API service](api.md)).

## Layout of a screen

```
apps/web/src/app/(main)/<route>/page.tsx                 thin page, renders one feature component
apps/web/src/components/finance/<screen>/<screen>.tsx    client component with the screen's state and mutations
apps/web/src/components/finance/<part>/                  finance building blocks (BudgetLine, CurrencySwitch, charts, …)
apps/web/src/components/ui/<component>/                  project-wide building blocks (Page, Panel, Stack, Button, Dialog, …)
```

Every component is a folder with its component, test, `index.ts` and optional BEM stylesheet; pages import from the module barrels (`@/components/finance`, `@/components/ui`). The rules are in [Components and styles](components.md).

Pages under `(main)` share `ApplicationShell` (`apps/web/src/components/shell/application-shell/`):

- **Sidebar** (from `laptop` up): the logo, then the navigation from `apps/web/src/app/(main)/routes.ts`: Home, a **Money** section (Transactions, Review, Accounts) and a **Plan** section (Budgets, Upcoming, Analytics), with Import and Settings at the bottom (`NavigationSections`, `SetupRouteItems`). Review shows a count badge from `useNeedsReviewCount`. The `UserMenu` (name and email) closes the sidebar.
- **Header**: a search box that opens the Transactions page filtered by the text (`Ctrl+K` or `Cmd+K` focuses it) and, from `laptop` up, one global **New transaction** button.
- **Tab bar** (below `laptop`, `tab-bar.tsx`): a bar fixed to the bottom of the screen with Home, Activity (`/transactions`), a round add button in the middle that opens the New transaction dialog, Budgets, and More, which opens `NavigationDrawer` (`navigation-drawer.tsx`) with the full navigation and the account menu. More is highlighted on pages that have no tab (Review, Accounts, Import, Settings); the drawer opens with focus on the current page's link and gives focus back to More when it closes. The main content gets bottom padding the height of the bar (`size(tab-bar-height)`), so nothing hides behind it.
- The current page is marked with `aria-current="page"` by `isCurrentPath` (`apps/web/src/lib/navigation.ts`), which also matches sub-pages, so `/accounts/<id>` highlights Accounts.

## API client

`apps/web/src/api/client.ts` is the only place that calls `fetch`:

| Export                            | What it does                                                                                                                                                 |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `apiRequest(method, path, body?)` | Sends `/api/v1<path>` with `credentials: 'same-origin'` and a JSON body, returns the parsed JSON (or nothing for `204`). A non-2xx answer throws `ApiError`. |
| `apiGet(path, params?)`           | `GET` with a query string built from `params` (empty values are dropped).                                                                                    |
| `apiList(path, params?)`          | `GET` a collection and return its `items`.                                                                                                                   |
| `apiPages(path, params?)`         | Follow `nextCursor` until the last page and return every item.                                                                                               |
| `ApiError`                        | `message`, `status`, `code` and `fields` from the API's `{ error }` body.                                                                                    |

URLs are relative, so the browser sends them to the Next.js origin with the session cookie and Next.js rewrites them to the API. A `401` on anything other than `/auth/*` sends the browser to `/sign-in?next=<current path>`.

While a route under `(main)` loads, `app/(main)/loading.tsx` shows a page-shaped skeleton (a title, one `SkeletonText` line whose label screen readers announce, a card and a block) instead of a line of text. Screens render a query's lifecycle through `QueryContent` from `@/components/ui` (`pending` as pulsing `SkeletonText` lines that keep the loading text for screen readers, `error` with a retry button, an optional `empty` state, then the children render function) instead of chained ternaries. Budget rows, the budget summary and Home take a budget's pace, what is left and its state from `budgetFigures(budget, today)` in `apps/web/src/components/finance/budget-status.ts`, and the label, badge tone, bar tone and fill color of each state from `BudgetStates` there (see [Budgets › Budget status](../features/budgets.md#budget-status)). The report hooks keep their keys under `summary`, so invalidating `summary` after a write refreshes the breakdown and balances too.

Home (`/`) renders `Home` from `apps/web/src/components/finance/home/`: `HomeHero`, `NetWorthCard`, `AttentionStrip`, `SpendingBars`, `BudgetsToWatch`, recent activity and `CashFlowChart`, with the figures computed by the pure helpers in `home-figures.ts`. Home, Budgets, Accounts and Analytics share `CurrencySwitch` and `useCurrencyView` (`finance/currency-switch/`), which pick one currency or, on Home and Budgets, the converted view; `describeConversion` in `finance/conversion.ts` writes the "Approximate…" caption. Helpers shared by these screens sit at the root of `finance/`: `netWorthByMonth` and `shortMonthLabel` in `net-worth.ts` (Home's net worth sparkline, the Accounts trend, month labels on Analytics charts) and `compareWith` in `comparisons.ts` (the "vs last month" delta of a `Stat`, on Home and Analytics).

Analytics is four thin pages, `app/(main)/analytics/page.tsx`, `spending/page.tsx`, `cash-flow/page.tsx` and `payees/page.tsx`, each rendering `Analytics` from `finance/analytics/` with its `view` (`overview`, `spending`, `cash-flow`, `payees`) and the page's `searchParams`. `analytics.tsx` is the frame: the heading, the filter bar (`analytics-filter-bar.tsx`: currency, month, period, comparison) and the underline tabs, the `ui` `SectionTabs` (`Link`s with `aria-current="page"` and an optional count). The filters live in the URL: `parseAnalyticsFilters` in `apps/web/src/lib/analytics-filters.ts` reads `currency`, `month`, `range` (1, 3, 6 or 12) and `compare` (`previous` or `year`) with safe defaults, and `analyticsHref` builds the links, leaving default values out; a filter change calls `router.replace` so it does not add history entries. The views are `analytics-overview.tsx`, `analytics-spending.tsx`, `analytics-cash-flow.tsx` and `analytics-payees.tsx`; period arithmetic (`periodMonths`, `comparisonEnd`, `totalsOf`, `groupChanges`) is in `analytics-data.ts` and the Recharts charts (`MonthlyBars`, `StackedGroups`) in `analytics-charts.tsx`. See [Analytics](../features/analytics.md).

Upcoming follows the same pattern: `app/(main)/upcoming/page.tsx`, `recurring/page.tsx`, `subscriptions/page.tsx` and `suggestions/page.tsx` render `Upcoming` from `finance/upcoming/` with its `view` (`due`, `recurring`, `subscriptions`, `suggestions`). `upcoming.tsx` holds the heading, the **New recurring payment** action, `SectionTabs` (counts for what is overdue or due soon and for the suggestions), a `SectionIntro` with the section's explanation and steps from `upcoming-sections.ts`, and the series, record and link dialogs shared by every section. Lists inside a section are grouped with `ListGroup` (`upcoming/list-group.tsx`: a heading with a count and a hint, then divided rows). See [Upcoming and recurring payments](../features/recurring.md).

Accounts (`/accounts`) renders `AccountsOverview` from `finance/accounts-overview/`: `NetWorthTrend`, one `AccountGroup` per type group with its `AccountRow`s and `AccountActions` (Pay card and the row menu), `BalanceSummary` and `CurrencyTotals`; the grouping, totals and changes are pure helpers in `accounts-figures.ts`. See [Accounts](../features/accounts.md#the-accounts-page).

Types for rows (`TransactionRow`, `AccountSummary`, `CategoryTree`, `User`, …) are the response contracts in `packages/shared/src/schema/` (Zod schemas plus inferred types). The API serialises through the same schemas and the client imports them with `import type`, so the two never drift.

## Writing data

Every write is a function in `apps/web/src/api/mutations.ts` that calls `apiRequest` with the right method and path: `createAccount`, `updateAccount(id, values)`, `setAccountArchived`, `restoreAccount`, `createPayee`, `updatePayee`, `createTransaction`, `updateTransaction`, `categorizeTransaction`, `reopenReview(id, previousCategoryId)` (the Undo of the Review page: puts the category back and sets `needsReview`), `deleteTransaction(row)` and `restoreTransaction(row)` (a transfer leg goes to `/transfers/:transferId`, so both legs move together), `createTransfer`, `updateTransfer`, `linkTransfer`, the category and group functions, `updateSettings`, `upsertExchangeRate`, `deleteExchangeRate`, `restoreExchangeRate`, `createRule`, `deleteRule`, `restoreRule`, `applyRules`, `createTemplate`, `updateTemplate(id, values)`, `deleteTemplate`, `restoreTemplate`, `reorderTemplates(ids)`, `createSeries`, `updateSeries`, `deleteSeries`, `restoreSeries`, `recordDuePayments(today)` (Upcoming calls it once a day on load), `linkOccurrence(seriesId, dueOn, transactionId)`, `unlinkOccurrence(seriesId, dueOn)`, `previewImport`, `commitImport`, `upsertBudget`, `deleteBudget`, `copyBudgets`, and the account functions `signIn`, `signUp`, `signOut`, `updateProfile`, `changePassword`, `revokeSession`.

Components call them through `useMutation` (usually `useEntityMutation`, below), show a toast on success or `error.message` on failure, then call `useRefreshFinance()`, which invalidates every key in `FinanceKeys` (`accounts`, `budgets`, `categories`, `deleted`, `exchange-rates`, `payees`, `rules`, `settings`, `summary`, `transactions`). Deleting a transaction shows a toast with an **Undo** button that calls `restoreTransaction`.

Component tests mock the module (`vi.mock('@/api/mutations', () => ({ createRule: vi.fn(…) }))`) and seed the cache with `client.setQueryData(QueryKeys.…, data)`; see [Testing](testing.md).

## Authentication in the client

- **Pages.** `apps/web/src/app/(auth)/sign-in/page.tsx` and `sign-up/page.tsx` render the shell component `AuthForm` (`mode="sign-in"` or `"sign-up"`) inside `AuthScreen`. Sign-up asks for name, email, password and the password again; both forms call `signIn` or `signUp` and then go to the `next` query parameter. `safeNextPath` (`apps/web/src/lib/navigation.ts`) resolves `next` the way the browser would and keeps it only when it stays on the app's origin, so crafted values such as `//evil.example`, `/\evil.example` or `https://evil.example` fall back to `/` and a link cannot send the user to another site after signing in.
- **Route guard.** `apps/web/src/proxy.ts` (Next.js 16's name for middleware) redirects any page request without a `__Host-ck_session` or `ck_session` cookie to `/sign-in?next=…`. It does not check that the session is valid; the API does that on every call, and the API client redirects on `401`.
- **User menu.** The shell component `UserMenu` shows the user's initials (and the name in the sidebar), the name and email, links to Settings and Deleted items, and Sign out, which calls `signOut`, clears the React Query cache and goes to `/sign-in`. It sits at the bottom of the sidebar and of the navigation drawer on phones and tablets.
- **Settings.** `SettingsView` has eight tabs: Profile, Categories, Budget period (`BudgetPeriodSettings`: the rule, the weekend and moving the current period through `usePeriod`, `movePeriod` and `resetPeriod`), Currencies, Rules, Templates, Security and Deleted items; the Categories, Currencies, Rules, Templates and Deleted items tabs link to their own pages (`/settings/templates` renders `TemplatesSettings`), and the Categories tab also holds the **Emoji for categories and payees** switch (`EmojiPreference` in `settings-panels.tsx`, saving `allowEmoji` through `updateSettings`; off by default, hidden in the component preview). Settings › Profile holds `ProfileForm` (name and email, `PATCH /me`); Settings › Security holds `PasswordForm` (current password, new password twice) and `SessionList` (active sessions, each other than the current one with a Sign out button). See [Account and security](../features/account-and-security.md).
- **Hydration.** `useHydrated()` (`apps/web/src/lib/hydration.ts`, built on `useSyncExternalStore`) returns `false` on the server and during hydration and `true` afterwards. Settings reads the current user through it, because the shell may already have cached `/me` by the time the streamed Settings page hydrates, and rendering that data straight away would not match the server HTML.

`DeletedItems` (`apps/web/src/components/finance/deleted-items/`, route `/settings/deleted`) lists deleted transactions (transfers included), accounts, rules and exchange rates in four tabs, each row with a Restore button. ## Forms

Forms use React Hook Form with `zodResolver` and the schemas in `packages/shared/src/schema/`. Money fields are text inputs (`inputMode="decimal"`) whose value is sent as a string and parsed by the API in the account's currency. Dates are `YYYY-MM-DD` strings picked with the shared calendar popover.

Dialog forms are assembled from shared pieces rather than written field by field:

| Piece                                                      | File                                                                                                | What it gives you                                                                                                                                                                                                                                 |
| ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TextField`, `AmountField`, `DateField`                    | `apps/web/src/components/ui/form-fields/`                                                           | A `FormField` wrapper taking `control`, `name`, `label` and `description`; `AmountField` is the decimal text input, `DateField` the calendar popover.                                                                                             |
| `DialogFormFooter`, `saveLabel`, `CreateNewTrigger`        | `apps/web/src/components/ui/dialog-form/`                                                           | The Cancel + submit row (an optional `secondaryAction` before them, such as **Save as template**; spinner while pending; `saveLabel(editing, 'Create')` yields "Save" or the create label) and the "Create new" row pickers use to open a dialog. |
| `useEntityMutation`                                        | `apps/web/src/components/finance/use-entity-mutation.ts`                                            | `useMutation` plus the success toast, invalidation of every `FinanceKeys` query and the caller's follow-up (reset, close, callback).                                                                                                              |
| `AccountField`, `PayeeField`, `CategoryField`, `MemoField` | `apps/web/src/components/finance/transaction-dialog/transaction-fields.tsx` (private to the dialog) | The transaction pickers as form fields.                                                                                                                                                                                                           |
| `AccountFormFields`, `accountDefaults`, `saveAccount`      | `apps/web/src/components/finance/create-account-dialog/account-fields.tsx` (private to the dialog)  | The account form's type, currency and detail fields and its create/update wiring.                                                                                                                                                                 |

The transaction dialog (`apps/web/src/components/finance/transaction-dialog/`) has three modes, expense, income and transfer, and works for both creating and editing; editing a transfer leg edits the whole transfer. Its default values come from `standardDefaults` and `transferDefaults`, which merge an existing row or a caller preset with blank values.

## Dates and the current month

Transaction dates are calendar days (`YYYY-MM-DD`) with no time zone, so every "today" in the web app is the user's local day: `localIsoDate(new Date())` for the default date of a new transaction, an account's opening balance and a new exchange rate, and `currentMonth()` (`localIsoMonth(new Date())`) for the month Home, budgets and transactions open on. Both helpers live in `packages/shared/src/lib/date-helpers.ts`. Never take today from `new Date().toISOString()`: that is the UTC day, which differs from the user's day around midnight, so a transaction entered just after midnight on the 1st would land outside the month on screen. The web app always sends the month and dates it means; the API's own defaults (`month` on `/reports/summary`, `openingDate`) use UTC because the server does not know the user's time zone.

## Pickers

- `AccountPicker` and `PayeePicker` (`apps/web/src/components/finance/`) wrap `EntityPicker` (searchable popover with a "Create new" dialog).
- `CategoryPicker` (`apps/web/src/components/finance/category-picker/`) is the category autocomplete used everywhere a category is chosen: the transaction dialog, Review, the budget and payee dialogs, the rules page and the inline chip in `TransactionTable`. It builds on `Combobox` (`apps/web/src/components/ui/combobox/`, cmdk in a `Popover`) with a `field` or `chip` trigger. Sections are Suggested (from `suggestedId`), Recent (the last five picks) and one per group; typing filters categories and groups, every word must match (`matchesSearch`); "Leave uncategorized" clears it; the footer links to `/settings/categories`. Pass `kind` when the direction is known. See [Categories › Pick a category](../features/categories.md#pick-a-category).
- `IconPicker` shows the curated registry as a searchable grid; `ColorPicker` offers a palette plus a custom colour input. Both live in `apps/web/src/components/ui/`. When the `allowEmoji` setting is on, callers pass `allowEmoji` and `IconPicker` adds an **Emoji** field that accepts exactly one emoji (`isEmoji` from `packages/shared/src/lib/patterns.ts`); the category dialog and the payee dialog do. `Icon` draws an emoji value as text instead of a Lucide icon, so every place that renders a category or payee icon handles both.
- The payee dialog (`CreatePayeeDialog`, `finance/create-payee-dialog/`) holds the name, the usual category and a **Look in lists** section (`payee-appearance.tsx`, private to the folder): a live `PayeeAvatar` preview, `ColorPicker`, `IconPicker` and **Use initials**, which clears both. See [Categories › Payee look](../features/categories.md#payee-look).

## Remembered in the browser

A few conveniences live in `localStorage` only, so they are per browser, missing in a private window and never sent to the API:

| What                                                         | Where                                                                                                                                                                 |
| ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| last account and transfer pair in the dialog                 | `rememberedValue` / `rememberValue` in `apps/web/src/lib/form-memory.ts` (`RememberedFields.standardAccount`, `transferFrom`, `transferTo`)                           |
| the last five categories picked                              | `rememberedList` / `rememberInList` in the same file (`RememberedFields.recentCategories`), read by `CategoryPicker`                                                  |
| the currency picked on Home, Budgets, Accounts and Analytics | `rememberedValue` / `rememberValue` (`RememberedFields.currencyView`), read by `useCurrencyView` after hydration; an unknown value falls back to the primary currency |
| entries cleared on Review today, for **Undo**                | `apps/web/src/components/finance/review-inbox/reviewed-today.ts`, keyed by the local date and dropped the next day                                                    |

Every read and write is wrapped in `try`/`catch` and the screen works without the stored value. Anything shown from it on first render must wait for `useHydrated` (the Reviewed today list does) so the server render and the first client render agree; the recent categories only appear once the autocomplete is open.

## Styling

- One light theme. Every design value lives in the SCSS theme in `apps/web/src/styles/theme/`; `apps/web/src/styles/tokens.scss` emits it as CSS custom properties and `apps/web/src/app/globals.scss` holds the resets (inside `@layer reset`). Stylesheets use `var(--…)` or the theme functions; Stylelint rejects literal colours, type sizes, radii, borders, shadows and z-indexes elsewhere. See [Components and styles › Theme](components.md#theme).
- The fonts are Inter for text and Source Serif 4 for headings and hero figures, loaded with `next/font/google` in `apps/web/src/app/layout.tsx` and served from the app.
- Colours needed from TypeScript come from `Colors` in `apps/web/src/styles/theme.ts` and Recharts style objects from `ChartStyle`; both hold `var(--…)` strings. ESLint rejects literal colours in any other file. See [Code style](code-style.md).
- Icons with a meaning get a fixed colour from the theme: `MetricCard` and `MetricIcon` (`finance/metric-icon/`, the icon in the Home hero and Analytics figures) take a `kind` (`income`, `spending`, `kept`, `budgeted`, `netWorth`, `rate`, `total`) that `apps/web/src/constants/metrics.ts` maps to a Lucide icon and a `--color-metric-*` colour; accounts get one icon and colour per type from `accountTypeStyle` in `apps/web/src/constants/account.ts` (`--color-account-*`). Both render in a tinted `Avatar`: circles for metrics, rounded squares for accounts.
- Everything else is a stylesheet named after its component, holding one BEM block (`budget-line.scss` → `.budget-line`, `.budget-line__meta`). Components write the class names as plain strings and combine them with `cn()` from `apps/web/src/lib/styles.ts`. Layouts are mobile-first with the breakpoint mixins in `apps/web/src/styles/abstracts/`. See [Components and styles](components.md).
- Group colours come from the database and are applied inline (`style={{ background: group.color }}`); no per-category colours exist.
- Icons render through `Icon` (`apps/web/src/components/ui/icon/`), which only knows the names in `packages/shared/src/constants/icon-names.ts` (the lucide component map in `apps/web/src/constants/icons.ts` must cover exactly those names). Unknown names fall back to a question mark. Add icons to the registry, never import the whole lucide package.

## Adding a screen

1. Create the feature folder `apps/web/src/components/finance/<screen>/` (component, test, `index.ts`), export it from `finance/index.ts` and render it from a page under `apps/web/src/app/(main)/`. Build it from `ui` components; add a stylesheet only for a look no component provides.
2. If it needs a new endpoint, add it to the API first ([API service › Adding an endpoint](api.md#adding-an-endpoint)), then a hook in `use-finance-data.ts` (key in `QueryKeys`, and in `FinanceKeys` if writes should refresh it) and, for writes, a function in `apps/web/src/api/mutations.ts`.
3. Add the route to `apps/web/src/app/(main)/routes.ts` if it belongs in the sidebar.
4. Write the component test `<screen>.test.tsx` with a prefilled `QueryClient` and `vi.mock('@/api/mutations', …)` (see `deleted-items/deleted-items.test.tsx`).
5. Document it under `docs/features/` with screenshot placeholders.
