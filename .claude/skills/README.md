# Project skills

> Summary: index of the Claude Code skills that live in this repository, one line each, with when to use them, how they are laid out, and how to test them.

Each skill is a folder with a `SKILL.md` (frontmatter `name` and `description`, then the instructions) and the files it references. Claude Code loads them automatically for this project; invoke one with `/<name>` or let it trigger from its description. Keep this table in sync when a skill is added, renamed or removed, and keep `agents/workflows.md` › Project skills by task pointing at the right skill.

## Layout of a skill

- `SKILL.md`: frontmatter (`name` equal to the folder, a third-person `description` that says what the skill does, when to use it and which sibling to use instead), then a short workflow under 500 lines that links the `agents/` docs instead of repeating the house rules.
- `references/*.md`: one topic per file, one level deep, each starting with a `> Summary:` line; files over 300 lines start with a table of contents. `references/source.md` credits the upstream skills each one was adapted from and their licence.
- `evals/evals.json`: realistic CoinKeeper tasks with objectively checkable assertions, in the format of the `skill-creator` skill. `evals/trigger-evals.json`: queries that should and should not load the skill. `react-client-patterns` also has `evals/rule-cases.json`, good and bad code per rule.

Code examples in skills follow the same rules as the code base (`agents/conventions.md`, `agents/components.md`): no comments, named constants, `type` over `interface` except for module augmentation, Zod contracts from `packages/shared`, integer minor units, soft delete, BEM.

## Testing a skill

Run the evals with the `skill-creator` skill after changing a `SKILL.md` or a reference: each prompt once with the skill and once without, graded against the assertions. A change is ready when no assertion fails in every run with the skill and no eval scores lower with the skill than without it. Tune the `description` with `trigger-evals.json` when a skill loads for the wrong requests or misses the right ones. Some eval assertions name files or lines in the current code; update them when that code changes.
